# Judges Verification Guide: Claims to Evidence

This document maps every protocol claim to a reproducible verification command, expected output, and source or artifact file.

All offline verification commands run on a fresh clone with Node.js 22.18+ (Node 26 in CI) and Rust installed, without network connectivity or private keys. Commands that query the public blockchain or download external sandbox binaries are explicitly labeled `(needs network)`.

## What is not claimed

To maintain transparency and rigor, the following boundaries define what Scrip does and does not claim:

1. **Not formal mathematical verification:** Core accounting invariants (P1 through P10) are verified using property-based testing (`proptest`), invariant tests, and mutation coverage, but have not been proven using machine-checked formal proof systems (such as Coq or TLA+).
2. **Not an external commercial audit:** The codebase underwent two internal audit passes and mutation testing, but has not received an independent review from a commercial security audit firm.
3. **Testnet deployment only:** All contracts, transactions, and live wave executions took place on NEAR Testnet (`testnet`). No mainnet deployment is active.
4. **Relayer availability is not decentralized:** The facilitator relayer sponsors gas and manages transaction queues. If the relayer is offline or censors requests, transactions pause until an alternative relayer is configured or the funder submits directly.
5. **Multi-tenant token pooling boundaries:** When multiple mandates share a single contract deployment, token isolation relies on internal accounting ledger bookkeeping. Full cryptographic isolation requires dedicated sub-account envelopes per task.
6. **Agent demos are not a model-robustness benchmark:** The scripted demo agent obeys 100% of injected instructions by construction. The real-model trials use four small open models (1.7B to 4B parameters) on CPU, with 20 seeds per condition (fewer for any model whose row says so); they show how often such models obey an injected note, not how robust frontier models are. Only six recorded decisions were replayed on testnet, and the overcharge condition models a dishonest merchant rather than a model reasoning failure. The claim is that the contract bounds the loss whatever the model decides.
7. **Skipped testnet cases:** Layer E cases marked `SKIPPED` were not executed due to testnet RPC rate limits (HTTP 502/429) and are never counted as passed.
8. **General security notice:** Zero breach claims apply strictly to the specific cataloged attack scenarios executed, and do not constitute a guarantee of absolute or universal security.
